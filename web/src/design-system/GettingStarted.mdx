# Agentic Identity Broker Design System

Welcome to the **Refined Trust Architecture** design system for the consent management frontend.

## Overview

This design system provides a comprehensive component library optimized for capturing consent from non-technical end-users who delegate permissions to AI agents. Every component is designed to communicate **trustworthiness, clarity, and control**.

## Design Philosophy

### Refined Trust Architecture

The aesthetic is **exact, sober and accountable**. This is where users decide what an agent may do in their name, so the interface states facts, asks one question, and does not sell. The public docs site shares the same language (ADR 048).

**Core Principles:**

- **Hierarchy Through Size, Not Weight**: Geist at weights 400 and 500 only; nothing is bold
- **One Accent**: Jade marks the primary action, links and the granted state. Everything else is ink on a cool neutral ground
- **Containment Through Hairlines**: Cards sit behind a 1px hairline. One floating shadow serves overlays only
- **Motion That Guides**: One easing curve, 150 to 300ms, that never bounces
- **Whitespace as Structure**: Generous padding and hairline rules instead of boxes

## Typography

```css
Headings: Geist - 500 weight, letter-spacing -0.015em
Body: Geist - 400 weight, 500 for labels
Monospace: Geist Mono - 400 weight
```

## Color System

### Semantic Tokens

- **accent** (#0a7a66): The primary action, links, focus and the granted state
- **trust-deep** (#111827): Headings and primary text (ink)
- **trust** (#0a7a66): Same as the accent
- **trust-light** (#e7f3f0): Active navigation and tints
- **success-primary** (#0a7a66): Granted permissions, same as the accent
- **error-primary** (#b42318): Error states

## Accessibility

All components follow **WCAG 2.1 AA** guidelines:

- Keyboard navigation support
- Screen reader compatibility
- Visible focus indicators
- Proper ARIA labels
- Color contrast compliance
